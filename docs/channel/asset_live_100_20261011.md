# 100 并发真实素材、两个视频及删除联调（2026-10-11）

本次没有复现 HTTP 503、健康检查超时或 OOM；100 个素材创建成功，两个引用素材的视频生成成功。真实上游出现 HTTP 429：查询 19 次、并发删除 86 次，因此本轮不是全部请求成功，测试严格断言退出码为 1。

## 环境与流程

- 本地当前工作区代码，通过真实 HTTP 路由、Token 鉴权、素材归属、协议适配及视频任务持久化调用 `https://api.sctgx.cn`，项目 `nmyk`。未部署正式环境。
- 一个测试实例，真实 MySQL 5.7.43-log；随机隔离主库与日志库，连接池分别 30、5，GORM 预编译语句开启。Redis 和鉴权内存缓存关闭。
- 建立一个本次专用素材组，100 个请求同时创建 100 个不同素材 ID；参考图使用公共 OpenCV 水果图片，不包含真人。
- 每轮同时查询 100 个素材，轮次间隔目标 3 秒，共 54 轮、5400 次请求。每客户端最多一个在途查询，不积压重叠轮次；本次迟到轮次为 0。
- 选两个达到 Active 的素材，以 `asset://` 引用各创建一个视频。模型 `doubao-seedance-2-5-260628`，4 秒、480p、`generate_audio=false`，图片角色 `first_frame`。视频创建仅两次，无重提。
- 视频生成期间继续素材轮询；两个视频结束且下载完成后，100 并发删除本次素材，再删除本次素材组。
- 从创建前直到删除结束，`/api/ready` 每 500 ms 检查一次，`/api/status` 每 3 秒查询一次。
- 容器硬内存上限 1 GiB，不额外使用 swap，CPU 上限 2 核，PID 上限 256；Go 内存目标 640 MiB。复用的 MySQL 不在此容器限制内。
