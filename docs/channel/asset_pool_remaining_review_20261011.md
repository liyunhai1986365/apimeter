# 素材路径连接池风险修复（2026-10-11）

本轮只调整素材归属、别名关联、删除及自动组预请求，不修改视频任务提交、状态轮询、计费或任务表。这里的 `task` 是素材上传/处理返回的异步句柄，属于素材归属的一种别名。视频引用素材仍执行原有权限校验。

不改数据库结构，不迁移或批量回填历史数据，不限制素材创建和查询并发。删除保留此前每进程 4 个本地收尾槽位，等待槽位不借数据库连接。

## 五项风险的处理

| 原问题 | 当前处理 | 保留的边界 |
| --- | --- | --- |
| 单素材删除持锁枚举、更新全部别名 | 与组删除统一为规范身份撤销。只精确查目标 handle，按主键顺序锁定身份并重读 canonical，再更新身份标记；别名、素材处理任务及组内素材通过身份校验失效 | 历史归属行保留。身份变化时释放事务、重新计划锁；不任选歧义身份 |
| 上游成功后的归属收尾无限等待 | 素材登记/认领/撤销有 15 秒总预算，覆盖借连接、历史读取、锁等待和本地冲突重试；持锁事务的 Go context 最长 3 秒 | 成功创建和删除的收尾独立于客户端取消；数据库故障仍可能导致收尾失败，必须明确报错，不重放上游操作 |
| 首次登记及旧身份兼容扫描 | 按当前账号、类型和本次 canonical 集合筛选；每批最多 500 条，用主键游标分页，响应取消；兼容扫描始终放在写事务外 | `%canonical%` 没有独立索引，仍可能扫描账号范围。不能因“标记不存在”跳过历史撤销/别名校验 |
| 列表一次加载全部归属、不响应取消 | 列表 1 分钟总期限前移到本地归属预读及首个上游请求前；本地归属读取另受 15 秒预算约束，按 500 条分页，只读 `id,metadata`，批次间释放连接；控制器仅保留 handle/canonical 映射 | 为保留别名、用户隔离、精确总数和分页行为，仍枚举该用户在账号内的归属；并未宣称改成只查上游当前页的 ID |
| 自动组命中反复写同一缓存行 | 验证成功直接复用，取消更新时间和 Upsert；真正创建/替换组才写。失效更新附带旧值条件，避免旧验证结果覆盖新缓存 | 验证 HTTP 请求仍存在；相关 DB/HTTP 查询跟随请求取消，已确认成功建组后的归属及缓存收尾使用独立有界 context |

## MySQL 5.7 服务端锁等待

受控测试发现：只取消 Go context 虽然会归还应用池连接，但 MySQL 5.7 仍能保留正在执行的锁等待。本次实测在 3 秒客户端期限后仍残留 2 个服务端等待者，因此不能仅以 `pool.InUse` 降低作为锁已释放的证据。

素材写事务现在固定借用一条连接，临时把该连接的 `innodb_lock_wait_timeout` 降到最多 2 秒；原配置更短时保持原值。事务结束后在同一连接恢复原配置，恢复失败则丢弃连接，不把临时参数带给视频或其他业务。恢复参数最多等待 1 秒；这是事务结束后的连接清理期限，不是业务 SQL 超时。原事务 context 已取消时直接丢弃连接。没有修改全局数据库参数、隔离级别或 binlog 模式。

该设置约束的是单次 InnoDB 锁等待；Go 事务期限为 3 秒，归属操作整体期限为 15 秒。不是承诺所有 SQL 在服务器上都严格在 3 秒内结束。元数据兼容扫描不进入持锁事务，避免扫描放大持锁时间。MySQL 锁等待超时不会自动重试；死锁等已识别的本地事务冲突仍在同一总预算内回滚重试。

## 一致性和删除语义

- 登记或补齐一个响应中的素材及全部别名使用同一事务；冲突、锁超时或取消后不得部分登记。持久锁标记的预初始化不表示用户已取得素材权限。
- 已登记且关联不变的 GET 不更新归属、不取得组锁。首次发现新关联才进入短事务，锁内重新核验所有者、canonical 和撤销状态。
- 只有显式 DELETE 获得上游成功响应才撤销本地身份。DELETE 的 404/410 原样按接口约定返回，不补撤销；普通 GET、上游业务失败和网络失败也不撤销。
- 已授权发出的 GET 与删除并发时，继续透传已经拿到的上游结果，不恢复本地权限。
- 上游已受理但本地收尾失败时继续记录请求 ID，并提示联系管理员。后续 DELETE 的 404/410 不承担自动修复职责；不能宣称数据库故障下仍保证所有收尾成功。

## 验证范围

使用串行 Go 功能回归，以及已有 MySQL 5.7.43 容器中的独立临时测试库；限制 `GOMAXPROCS=2`、`GOMEMLIMIT=1GiB`、`go test -p 1`。未启动新数据库或大并发压测，未使用业务库。

回归覆盖：删除槽位等待期限及零连接占用、连接池耗尽时列表取消、真实身份锁等待后的连接释放/无部分登记、服务端等待者清理、会话配置恢复、同组创建与删除顺序、别名补齐与删除竞争、历史别名及组撤销、404/410 透传、自动组缓存零重复写入、预请求取消、受理后的有界收尾、视频素材权限及视频任务回归。

最终验证通过：MySQL 5.7 模型回归 29 项、接口回归 15 项；串行 Go 素材及视频任务回归通过（model 2.651 秒，controller 30.580 秒）。

最终 MySQL 5.7 受控锁测试中，登记约 3.005 秒返回；应用池仅剩故意持锁的测试连接，阻塞源尚未释放时服务端等待者已经清零，登记没有部分落库。提交和回滚后的连接参数恢复测试均通过。

小规模验证不能证明任意并发下均无 503。仍需关注必要的首次历史扫描、列表总量，以及实际连接池/数据库吞吐；不通过扩大连接池或无限等待掩盖这些限制。

## 部署要求

所有承接素材请求的实例都必须理解素材及父组身份撤销标记后再切流；旧实例不能与新版混部承接素材请求。历史所有权记录不再逐别名改为 invalid，因此只回滚部分实例会恢复旧的读取语义。
