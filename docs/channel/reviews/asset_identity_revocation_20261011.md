# 素材归属与组撤销调整（2026-10-11）

本次不改数据库结构，不迁移或批量回填历史记录，不限制素材创建和查询的并发。

## 查询与历史归属

- 当前渠道、账号内的组和素材查询兼容历史非零 `user_id/token_id`；归属仍以 `state_value` 中的用户为准。重复登记检查和写入路径读取同一条既有记录，不插入零值 tuple 副本；补齐新字段时保留原主键及用户/Token 字段。
- 登记 task/asset 别名时也读取历史 tuple，先恢复既有 canonical 身份，再验证撤销状态。未检查的身份不能当作有效身份初始化。
- 查询、列表、视频引用、历史认领和登记共用素材身份及父组的有效性校验。被撤销的已有 handle 仍是“已登记”，不能再次自动认领。
- 查询只读，不新建锁标记、不更新时间、不回填父组。已经授权发出的 GET 与删除并发时，继续保留原约定：透传上游结果，不能恢复本地归属。

## 删除素材与组

素材和组删除统一按主键顺序锁定目标身份，重新确认指定 handle 的 canonical，提交持久撤销标记。事务不扫描 metadata、不枚举或逐行修改全部别名及子素材；没有后台清理依赖。原归属记录仍保留，但读取会通过自身及父组标记判断失效。

创建/补齐关联时共享锁定父组身份及其 canonical；删除使用排他锁。先提交的创建也会被后续组撤销覆盖；删除后到达的创建/认领不能恢复子素材。同一素材的所有别名共用父组关系，包含尚无 GroupID 的旧别名。

删除收尾独立于客户端取消，有 15 秒业务期限（包括删除槽位、连接池和行锁等待）。只有本地删除操作收到上游成功响应（HTTP 2xx 且业务结果成功，或成功的空响应）才执行本地撤销。上游返回 404/410 时，无论错误码是否表示资源不存在，均透传上游响应，不补做撤销、不增加本地撤销重试响应头。普通网关 404、权限错误、网络错误和 GET 也不触发撤销。

单素材删除遵循相同的成功确认规则及 15 秒总预算。上游删除成功但本地撤销失败时，返回 `asset_binding_failed` 并提示联系管理员；后续删除若收到 404/410，也只透传，不能通过该响应自动修复本地归属。

素材登记、认领、撤销事务的 Go context 最长 3 秒；MySQL 5.7 同时在借用的连接上临时设置最多 2 秒的 InnoDB 锁等待，结束后恢复参数，恢复失败丢弃连接。只关闭客户端连接不足以终止 MySQL 服务端正在执行的等待。该参数不修改全局配置，也不传递给后续视频或其他业务。

## 关系与兼容查询

自然新增或补齐关联时，在已有身份标记的 Metadata 记录父组集合，使用 `lifecycle-v2` 标识。正常已登记素材通过现有唯一索引读取身份及父组。

对于缺少关系信息的旧记录，以及首次出现的身份，按本次 canonical/组 ID 筛选历史候选，分批读取后用 Go 精确比较，并响应请求取消。保留转义 JSON、旧别名、同账号撤销记录的兼容性；读取发生在写事务之外。锁内发现 canonical、父组或关系版本变化，释放事务并重新解析、按主键顺序加锁。

由于 canonical/父组在旧 metadata 中没有独立索引，兼容查询仍可能扫描账号及类型范围；减少的是返回、传输、解码的无关记录，不能称为完全消除数据库范围扫描。

## 部署边界

所有承接素材请求的节点必须升级到理解父组撤销标记的版本后再切流。旧节点不具备相同的读取校验，不能与新版混部承接素材请求；回滚也不能只回滚其中一个节点。没有数据库迁移可替代这一应用语义要求。

验证使用串行 Go 测试、SQLite 功能回归及已有 MySQL 5.7.43 的独立临时库小规模锁回归，没有运行大并发压测或创建新的数据库服务。
