# 素材并发优化复测：不加索引、不改数据库结构

2026-10-26，同样的 10 万素材、1000 请求突发条件下，最终版本的创建、查询、列表全部成功，主库 SQL 和健康检查均无错误。原有数据库字段、索引、迁移代码均未改动。

完整数据：[优化后 JSON](./assets_mock_100k_1000_optimized_20261026.json)。对照：[优化前报告](./assets_mock_100k_1000_20261026.md)。

## 修改内容

1. **合并并发创建的历史关联读取。** 相同数据库、渠道、账户、资源种类的请求按短批次检查。少量目标保留原有选择性查询；大量不同目标通过现有索引流式扫描一次，在 Go 中精确匹配，仅保留请求涉及的历史记录。新到请求进入下一批，没有跨批次缓存。写入仍逐请求执行，并在原有事务锁内检查最新身份、父组及归属冲突。
2. **按已有复合索引分页。** 固定账户范围内，先枚举旧数据可能使用的 user/token 元组，再按 `state_key` 继续读取，避免每批按主键重新排序大范围记录。MySQL 批量身份读取改为逐项完整唯一键查找，SQLite/PostgreSQL保留可移植查询。
3. **合并同时进行的相同列表扫描。** 用户、渠道、账户、项目、筛选、分页、上游 URL、凭证等均进入合并键；只共享正在执行的扫描，不缓存完成结果。每个请求返回前再次批量核验页内素材的当前归属和撤销状态。一个调用方取消不影响其他调用方；最后一个等待者取消时停止扫描。
4. **降低列表内存占用。** 扫描仍计算用户过滤后的精确总数，但只保留请求页的响应内容，不保留所有素材的完整响应。归属及去重映射仍与素材数量相关。

实现主要位于 `model/asset_binding_history_batch.go`、`model/asset_binding_read.go`、`model/asset_binding_identity.go`、`controller/asset_list.go`、`controller/asset_list_inflight.go` 和 `pkg/inflight/`。

保持单个测试容器 4 CPU / 2 GiB、Go 内存目标 1400 MiB、主连接池 30、日志连接池 5、MySQL 5.7.43、Redis 关闭、mock 每请求延迟 1 ms、HTTP 客户端超时 20 秒。

10 万素材仍属于同一用户、同一渠道账户、同一组，初始约 30 万条状态记录；mock、压测客户端和网关同处测试容器。预置耗时 21.81 秒，请求阶段 18.39 秒，总测试耗时 40.35 秒。

最终运行的创建、新素材查询、列表均记录到 1000 个同时在途请求；已有素材查询发起 1000 请求，观察到的峰值为 988。因此 1000 并发详情查询的完整证据来自新素材查询的三轮。

监控每 100 ms 采样，所有阶段锁等待事务峰值为 0，未出现 MySQL 1205/1213。加锁 SQL 最大耗时 **6.22 ms**，采样持锁事务年龄上界 **1000.81 ms**。事务年龄受 MySQL 秒精度时间戳影响，不是精确持锁时长；采样不能排除更短的锁等待。

新版本完成更多查询，总 SQL 数 74,468，不能直接与旧版本失败后只查询 22 个新素材的 SQL 总数作等工作量对比。池累计等待时间从约 31,431 秒降至约 2,806 秒，这是所有请求等待时间的累加，不是墙钟时间。

列表 mock 共收到 3019 次请求：单次列表 1010 页，并发列表阶段含 1000 次各调用方的第一页请求，以及共享扫描的后续 1009 页。没有把上游扫描并行度放大到 1000 份完整遍历。

## 验证与限制

- SQLite：素材模型、素材 HTTP 接口、官方/Ark 兼容接口和并发合并回归通过。
- 真实 MySQL 5.7：67 个顶层素材模型测试通过，包含历史记录、跨账户、别名、删除竞争、池等待截止时间及人为持锁超时。人为阻塞测试约 3.007 秒返回，除测试自己持有的事务外释放了连接。
- 针对新批量读取、跨页历史元组、请求取消、用户/筛选隔离、页内撤销校验及历史读取后的删除竞争，定向 `-race` 测试通过。
- 曾运行完整模型 `-race`；两个一次保存约 1000 条绑定的初始化夹具在插桩下超过原有 3 秒事务截止时间，未报告数据竞争。这两个夹具的普通模式回归通过；未扩大生产超时来迁就插桩测试。
- PostgreSQL 分支未运行实际服务器测试；新增通用查询通过 GORM 表达，MySQL 专用优化均有原查询回退。

**单次列表仍需遍历素材和上游分页以计算精确总数，当前约 6.7 秒。** 本轮并发列表是同一用户、同一筛选条件；1000 个不同用户/筛选条件无法共享同一次扫描，不能据此保证同样吞吐。创建的历史检查也仍有扫描成本，本次主要消除了并发突发中的重复工作。

该测试是突发并发，不代表持续 1000 QPS，也不代表真实上游网络延迟。测试未调用 MoreRouter 或真实素材服务。

两轮优化压测和模型回归共创建的 **85 个随机测试 schema 已清理并复核残留为 0**；**3 个测试容器及临时 DSN 凭证已清理**。三个容器均退出码 0，没有 OOM。
