# 素材关系按需补齐

既有素材的身份关系缺失或仍为 `lifecycle-v1` 时，首次访问按兼容逻辑还原关系并保存为 `lifecycle-v2`。后续访问直接读取关系，不再重复发现历史别名，也不获取写锁。已补齐的关系再次缺失时，仍会重新进入兼容路径。

## 实现

- 入口为 `filterActiveAssetBindings`，仅处理已经查到归属的素材；未知 ID 和其他用户的素材不会通过补齐获得归属。
- `loadAssetBindingHistoryForRead` 复用历史发现，覆盖同一身份的素材、任务别名、组别名、父组以及历史删除记录。发现过程在写事务外完成。
- `repairAssetBindingHistory` 按现有写入规则以主键顺序获取关系锁，比较事务内的状态与读取快照。并发新增父组或删除导致状态变化时，重新发现关系后再试。
- 仅持久化关系和撤销标记，不改素材归属记录、历史 user/token 元组、业务元数据或使用时间。补齐失败会回滚，取消遵守现有超时；后续请求可重试。
- 复用现有状态表和索引，没有新增表、列或索引。

## 范围

本次没有执行全量历史迁移，也没有建立账户级的“历史已清空/全部已补齐”标记。首次创建及发现新别名仍保留原有兼容校验，不能把关系不存在直接当成全新素材。

列表为了返回精确总数而枚举素材、请求上游分页的行为不变。此前 10 万素材、1000 并发的报告属于上一轮优化，本次未重跑该压力场景。

所有正常写入继续在同一事务中维护归属与关系。直接向数据库导入旧别名时，也必须维护关系或使对应关系完成标记失效；仅凭一个已有的完成标记，无法检测绕过写入流程的新历史记录。

## 验证

- SQLite 素材模型及本地 mock 接口回归通过。
- 本次补齐相关定向 `-race` 检查通过。
- MySQL 5.7.43 的全部 `TestAsset*` 模型测试通过，使用独立临时数据库。
- 覆盖首次补齐、补齐后无历史扫描/无写锁、再次缺失、旧版关系升级、跨账户及用户隔离、历史撤销记录、并发补齐/删除/父组变更、失败回滚与取消后重试。
- 未运行真实 PostgreSQL 服务；补齐使用现有跨数据库查询与锁辅助方法。
