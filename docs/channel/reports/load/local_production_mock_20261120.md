## 新建渠道的缓存延迟

创建渠道后立即转发时，数据库已经有渠道和能力记录，内存中的渠道表尚未刷新。本轮轮询记录为 **59 次 HTTP 503，59.32 秒后首次 HTTP 200**，与 `SYNC_FREQUENCY=60` 一致。

相关实现：`controller/channel.go:847` 调用 BatchInsertChannels 后仅重置代理客户端缓存；`model/channel.go:533` 批量插入事务提交不刷新渠道缓存；`model/channel_cache.go:123` 每隔 frequency 秒调用 InitChannelCache。因此新增渠道短时不可用是本次真实进程测试确认的现有行为。这些位置不在本轮未提交修改中；当前仅记录，未新增补丁，也未重新联网核对官方最新版本。

最终“通过”中的渠道可见性检查要求在既定周期内变为可用，并没有断言新增后立即可用。请勿把 242 项通过解读为这个延迟问题已修复。
