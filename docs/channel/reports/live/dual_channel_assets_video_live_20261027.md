# 双渠道素材并发与 Seedance 视频实测（2026-10-27）

当前代码编译后，通过本地完整网关实测：20 个用户、每渠道 10 个用户各 10 个素材，两个渠道同时各发起 100 并发创建。最终 200 个素材全部 Active，4 个引用素材的视频全部 succeeded。首轮有上游错误，不能表述为一次全部通过。

使用提交 `d422a3638dec30fa3b04172c90ba40f972c140d5`。原程序编译成功；实跑版本仅通过临时 Go overlay 增加 SQL、HTTP 上游和连接池观测，没有修改业务逻辑。复用旧环境的完整 MySQL 5.7.43 数据库 `apimeter_smoke`，启动前用户、渠道和素材记录均为 0。本次没有加载原 10 万历史素材库，因此不能替代 10 万历史数据场景测试。`NODE_TYPE=slave` 跳过迁移，未添加索引或修改表结构。

“整阶段耗时”是首个请求开始至最后一个完成，轮询包含轮次之间的 10 秒间隔；单次耗时不包含间隔。两渠道创建同时运行，总峰值并发 200。MoreRouter 首轮只有 92 个已创建素材，因此首次详情轮询峰值 92；补齐后和官方入口补测均实际达到 100。

MoreRouter 首轮创建 92/100 成功，8 次 HTTP 403 的内容为“无权操作此素材组，仅可操作自己创建的素材组”。HTTP 传输观测确认 8 次均已发往 `morerouter.cn`，并由上游返回 403；相同组的其他素材成功。本地查询组归属成功后，对这 8 个明确被拒绝的请求各补试一次，8/8 成功，未重试任何已成功创建的素材。供应商内部为何间歇判定无权限，现有证据不能进一步确定。

SCTGX 首轮创建 100/100 成功。初次 REST 查询出现 3 次上游 HTTP 429，下一轮全部恢复。官方 Action 补测又出现 3 次上游 HTTP 429，随后分别重查均为 200 / Active。成功 Action 响应均有 `ResponseMetadata` 和 `Result`，ID 与请求一致。MoreRouter 官方查询 100/100 一次成功。

唯一一次 30/30 采样发生在首轮创建阶段，前后相邻采样均未满载，二者相距 0.199 秒。因此不能说持续占满 0.1 秒或 1.2 秒：该次连续满载区间被相邻采样约束在约 0.20 秒以内，准确持续时间未逐事件记录。累计等待是多请求等待时间之和。

行锁每 200ms 查询 MySQL `INNODB_TRX`，未观察到 `LOCK WAIT`，采样事务年龄最大值为 0 秒；这不代表没有任何短暂行锁，也不代表精确测量了每个事务的持锁时长。结合全部业务请求、SQL 和健康检查，本轮未发现长时间本地阻塞、死锁、数据库超时或业务 5xx。首轮 403 及两次查询中的 429 均有上游 HTTP 状态观测佐证。
