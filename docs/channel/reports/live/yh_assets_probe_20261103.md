# YH 素材库与 H5 接口探测记录

- 日期：2026-11-03。
- API 基础地址：`https://www.yhapiplatform.com/v1`。
- 授权范围：用户提供测试凭据并允许非视频生成接口测试；本轮未提交任何视频生成请求。
- 测试层级：直接请求真实供应商，核对协议；尚未实现或验证本网关的 YH 适配。
- 配套证据：[脱敏请求记录](yh_assets_probe_20261103.json)。API Key、认证链接和既有资源明细不进入报告。
- 结果：40 次供应商 API 请求，HTTP 200 × 31、206 × 1、500 × 1、404 × 7。500 为 H5 名称校验错误；404 包含负向查询、删除后查询和旧任务 ID 删除失败。

## 1. 测试结果

| 接口/流程 | 结果 |
| --- | --- |
| 普通分组创建、列表、改名、删除 | 成功；创建直接返回 `data.group_id`，无需依赖列表猜测新 ID |
| `POST /v1/assets/async` | 成功；立即取得真实 `asset-*`，随后 `Pending → Processing → Active`，ID 不变 |
| 素材查询、名称更新、按组列表 | 成功；列表使用 `items/total_count/page_number/page_size` |
| 素材内容 Range 请求 | 成功；请求 `bytes=0-63`，返回 HTTP 206、64 字节、`Content-Range: bytes 0-63/82429` |
| `POST /v1/assets` 旧异步上传 | 成功；初始返回 `task-*`，用该 ID 查询最终得到真实 `asset-*` |
| 两张有效图片的批量上传 | 成功；两个条目均进入 Active 并返回真实素材 ID |
| 有效图片与不存在 URL 的混合批次 | 两个条目均进入 Failed，错误为“素材处理失败”；本轮没有得到一成功一失败的结果 |
| H5 链接创建 | 24 字符名称返回 HTTP 500；8 字符名称返回 HTTP 200 和认证链接 |
| 真人组列表 | HTTP 200、空列表；未完成真人认证，因此未创建真人组 |
| 不存在的素材、批次、视频任务查询 | 均返回 HTTP 404；视频仅查询随机构造且不存在的 ID |
| 新异步素材的真实 ID 删除 | 成功，后续查询 HTTP 404 |
| 旧异步任务 ID 删除 | HTTP 404；不能把“任务 ID 可以查询”推断为“任务 ID 可以删除” |

测试图片使用 OpenCV 的公开 fruits.jpg 和 baboon.jpg；没有上传真人照片。素材引用视频、视频模型能力、1080p、实际视频扣费和 HTTP 402 均未测试。

## 2. 对适配有用的实际响应

### 分组创建

```json
{
  "code": "success",
  "data": {
    "group_name": "<供应商账号前缀与测试名称>",
    "group_id": 5510
  }
}
```

创建时 ID 字段是 `group_id`，列表和更新返回的是 `id`。官方入口应将它们统一为字符串 `Result.Id`。创建/更新的 `group_name` 可能包含供应商用户及 Token 标识，不能直接当成客户展示名称。

普通组列表为 `data[]`，本轮创建前后分别返回 100、101 条，删除后恢复为 100 条；真人组为 `data.items[]`。未完成真人认证，未验证两种列表是否有重叠。

### 素材详情及列表

- 新异步创建返回真实素材 ID，状态为 `Pending`；第一次详情查询返回 `Processing`，之后 `Active`。
- 处理中 `url` 可以是空字符串；只有状态 Active 且取得有效结果后才能作为可用素材处理。
- `create_time` 实际格式为 `YYYY-MM-DD HH:mm:ss`，与文档 RFC3339 示例不同；不能无依据地把无时区时间当成 UTC。
- 列表总数位于 `data.total_count`，不是 `data.total`。
- 旧异步查询发生 `task-* → asset-*` 转换。网关应登记别名，修改、删除及视频引用优先使用已解析的真实 ID。
- 同一图片在本轮旧异步上传和全有效批次中返回相同真实素材 ID；不能假设每次上传都产生新的素材 ID。

### 批次状态

创建响应带批次级 `status`，但查询响应主要为 `batch_id/items/total_count`，本轮未返回批次级 `status`。应根据 `items[].status` 判断是否全部结束。

处理中，多个条目的 `id` 都可能等于同一个批次 `task-*`；成功后才回填各自的真实素材 ID。批次归属和逐项关联要分别处理，不能把处理中的重复任务 ID 当成多个已完成素材的唯一 ID。

混合有效/无效 URL 的批次最后全部 Failed。全有效 URL 批次随后全部 Active，说明批量接口能够成功，但混合批次并非本轮假定的部分成功交付。需要按实际逐项结果返回，不能替供应商构造成功条目。

## 3. H5 现有实现与本轮发现

本地已有 TgxMaas、火山官方、有你有剧的 H5 接口适配。它们使用上游的 `BytedToken/H5Link`，再调用结果查询或真人组兑换接口；共用会话归属、过期校验及官方响应包装。现有 TgxMaas/有你有剧相关测试主要通过 Mock 覆盖协议和隔离行为，不能当成真人刷脸实测证据。

YH 本轮成功响应为：

```json
{
  "code": "success",
  "data": {
    "h5_url": "<已脱敏>",
    "tip": "请让授权方在 120 秒内打开并完成认证，链接使用后失效"
  }
}
```

链接域名为 `ark.volcengine.com`，返回字段仅有 `h5_url/tip`，没有 `BytedToken`。本轮未打开或消费该链接，也未完成真人刷脸；链接按供应商说明自然过期。真人组列表在创建会话后仍为空。

首次使用 24 字符 ASCII 名称，返回：

```json
{
  "code": "error",
  "message": "artist_name 最多支持 32 个字符。为保证火山侧 group 名称不超长，请缩短艺人名后重试"
}
```

改用 8 字符随机名称后成功。供应商可能将内部账号前缀计入上游组名长度，但本轮未证明具体计算规则；不能将文档的 32 字符直接当作所有账号可用的用户输入长度。适配建议采用短的唯一关联名，用户展示名称另行保存。

YH 仍需本地会话句柄与真人组关联逻辑，可以复用已有归属和响应设施。成功刷脸后的名称回传、组 ID、失败/过期区分及官方 `CallbackURL` 语义尚未验证。

## 4. 错误处理

本轮观察到多种错误结构：

```json
{"code":"error","message":"素材不存在"}
```

```json
{"error":{"message":"素材不存在"}}
```

```json
{"error":{"code":"NotFound","type":"Not Found","message":"The request failed because the task was not found.","param":"task_id"}}
```

按已确认方案保留 HTTP 状态及可用业务错误，接入现有错误流程。没有为获得 402 而创建或查询真实收费视频任务。

## 5. 清理与未覆盖范围

仅创建并清理本轮专用分组及其中的测试素材。新异步素材删除后详情为 404；旧任务 ID 删除返回 404 后，通过删除本轮测试分组完成级联清理。分组列表恢复至测试前的 100 条，本轮分组已不在列表中；两个成功批次素材的真实 ID 查询均为 404。没有修改或删除已有分组。

以下保留后续验证：

- 真人本人完成 H5 后的完整流程、真人素材上传和专用删除。
- 新异步上传 Webhook 的参数支持和真实投递：本轮未配置公网回调接收端。
- 跨 Token 转移：只有当前凭据，没有经过验证的目标 Token，本轮未转移分组。
- 视频生成中/失败/402，以及 1080p 生成；本轮明确禁止生成视频。
- 网关官方入口、归属隔离和计费回归；当前记录只证明供应商直连接口行为。

1080p 已按用户确认纳入 [接入规划](../../design/seedance_yh_integration_plan.md)，不是本轮视频生成实测结论。
