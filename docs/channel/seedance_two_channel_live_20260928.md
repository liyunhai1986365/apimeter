除读取供应商模型能力和下载公开参考图/视频结果外，素材和视频操作全部使用本平台 Key 调用本平台 HTTP 接口，由网关转发到供应商。

## 新确认问题与配置要求

**ASSET-04，P2：模型限制 Key 无法正常查询已授权模型的任务。** 两个 Key 初始均开启模型限制，白名单包含本次生成模型。提交成功，GET 查询均返回 403。对相同 Key、相同任务，仅关闭隔离实例的模型限制即返回 200；任务完成后再次开启得到 403，关闭得到 200。原因见[审查记录](asset_security_review_20260920.md)：原生 GET 未填模型名，通用分发器却先用空模型名校验白名单。

此次真实联调为继续取回视频，两个隔离测试 Key 最终关闭了模型限制；联调阶段没有修改业务代码。随后按用户要求修复 ASSET-04，并通过本地模拟上游回归，见[修复记录](asset_security_review_20260920.md)。本文及配套 JSON 保留修复前的真实联调结果，不代表已重新运行真实供应商测试。前三项已知问题仍按用户要求暂不修复。

另有两项实际接入要求，不认定为网关代码缺陷：

1. TgxMaas 的 `default` 项目返回“没有启用的火山素材渠道”。用户确认 `nmyk` 后创建成功；之前的 400 请求未创建分组，也没有提交视频。此结果不能证明先前提到的 EOF 与项目配置有关。
2. 有你有剧的列表要求 `Filter.GroupType`。补充 `AIGC` 后列表成功；调用示例应保留这一参数。

联调准备期间自建启动脚本曾遗漏 Redis 初始化，以及重启时读取了新生成而非已保存的平台 Key，分别在本地鉴权阶段导致 500/401。均在发往供应商之前失败，修正的仅是临时启动脚本和客户端配置，不属于业务代码或供应商缺陷。
