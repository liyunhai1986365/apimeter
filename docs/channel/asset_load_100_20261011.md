# 100 个素材创建及每 3 秒轮询测试（2026-10-11）

结论：本次未复现 503。100 次创建、2000 次素材状态查询、116 次就绪检查和 20 次服务状态查询全部返回 HTTP 200，无客户端错误或轮询积压。

## 测试范围

- 使用当前未提交代码的真实 HTTP 入口、Token 鉴权、素材控制器和持久归属逻辑；一个应用测试实例。
- MySQL 5.7.43-log，独立临时主库和日志库，结束后自动删除测试库；未操作业务数据。
- 主库连接池 30、日志库连接池 5，开启 GORM 预编译语句。Redis 和鉴权内存缓存关闭。
- 项目 nmyk，预先登记一个素材组；100 个同组素材同时创建。全部创建完成后，100 个客户端同步发起每轮查询，共 20 轮，轮次起点间隔 3 秒。
- 每个客户端每轮只发一个查询；下一轮不覆盖未结束的上一轮，业务在途请求最多 100。没有启动 100 个系统进程，也没有额外的大数据背景记录。
- 上游为本地 HTTP 响应，每次延迟 20 ms；每个素材前 3 次查询返回 Processing，随后返回 Active。该状态变化仅用于检验透传，不代表供应商真实处理速度。
- /api/ready 每 500 ms 检查一次（另有启动探针），/api/status 每 3 秒查询一次。
- 只运行一个测试程序，GOMAXPROCS=2、GOMEMLIMIT=1GiB；未启动新数据库或修改全局数据库参数。

## 请求结果

| 操作 | 请求数 | HTTP 200 | HTTP 503 | P95 | 最大耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 素材创建 | 100 | 100 | 0 | 271.922 ms | 273.393 ms |
| 素材状态查询 | 2000 | 2000 | 0 | 91.223 ms | 98.196 ms |
| /api/ready | 116 | 116 | 0 | 2.541 ms | 33.651 ms |
| /api/status | 20 | 20 | 0 | 1.257 ms | 32.515 ms |

100 个创建请求同时释放，创建阶段总耗时 0.276 秒。创建、查询的客户端在途峰值均为 100。整体采样持续 57.364 秒（20 轮从第 0 秒到第 57 秒发起），迟到/积压轮次 0。查询状态分布为 Processing 300 次、Active 1700 次，均符合本地上游响应。

## 连接池及数据校验

- 主库使用连接采样峰值 30/30；每 5 轮输出的轮末 InUse 均为 0，没有观察到轮询积压。
- 主库借连接等待 16153 次，累计等待 61.205 秒，平均每次等待 3.789 ms。累计值是所有并发 SQL 等待之和，不是某个请求等待了 61 秒，也不是平均接口耗时。
- 日志库借连接等待 0 次。100 ms 采样没有捕获日志池正在使用的连接，不能解释成日志库未执行检查；全部就绪响应均验证了主库和日志库为 ok。
- 每 100 ms 独立采样测试主库中的 InnoDB 锁等待事务，观测峰值 0；监测错误 0。采样无法排除短于采样周期的瞬时锁竞争。
- 轮询前后，素材归属及锁标记行的完整快照一致；查询没有改写这些记录。最终逐个 ID 确认 100 个素材归属均存在且唯一。
- Go 测试及数据库清理全部通过。主库曾瞬时用满 30 个连接，但短暂排队没有发展成健康检查超时或 503。

## 复现入口及边界

测试用例：`controller/asset_load_mysql57_test.go` 中的 `TestAssetLoad100CreateAndPollMySQL57`。只在显式设置 `ASSET_LOAD_100=1` 和 `ASSET_TEST_MYSQL_DSN` 后运行，并检查 MySQL 版本必须为 5.7；普通测试默认跳过。`ASSET_LOAD_REPORT_PATH` 可保存统计 JSON。测试会创建随机隔离库，不复用 DSN 中的业务库。

结构化结果：`docs/channel/asset_load_100_20261011.json`。本次运行日志保存在 `/tmp/asset-load100-20261011.log`。

结论仅适用于上述单实例、100 素材和本地上游场景；不代表双实例、大量历史记录、真实上游延迟或 Redis 故障下也不会出现 503。本轮只增加可复用测试与报告，没有修改业务代码。
