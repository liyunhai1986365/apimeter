# 用户自有供应商视频任务错误退款：待处理问题

记录日期：2026-11-05。状态：**已确认，按用户要求暂不处理**。严重程度：P1（账务错误）。本次仅记录问题，不实施退款修复或历史账目调整。

## 触发条件与现象

任务使用 `BillingSource=user_owned_provider`（用户绑定自己的上游 Key，平台不扣钱包或 API Token 额度），但视频任务落库时保存了大于零的 `task.Quota`。提交成功后，如果任务转为失败，公共退款逻辑会把该额度退入用户钱包及关联 Token，形成未扣先退。

“用户自有供应商”是特定渠道归属和计费模式，不是指渠道仅供自己使用。管理员正常添加、通过平台钱包或订阅计费的 YH 渠道，不因供应商是 YH 而触发此问题。

## 原因与代码位置

1. [service/billing_session.go](../../../service/billing_session.go) 的 `preConsume` 将自有供应商实际预扣设为零，`Settle` 也跳过其资金结算；这一阶段行为正确。
2. [relay/relay_task.go](../../../relay/relay_task.go) 的提交逻辑仍将模型计价得到的 `finalQuota` 返回为 `TaskSubmitResult.Quota`；[controller/relay.go](../../../controller/relay.go) 随后将它写入 `task.Quota`。模型计算价格被保存为后续结算使用的已扣额度。
3. [service/task_billing.go](../../../service/task_billing.go) 的 `RefundTaskQuota` 直接按 `task.Quota` 退款。`taskAdjustFunding` 仅区分订阅与钱包，未排除 `user_owned_provider`；`taskAdjustTokenQuota` 同样缺少该判断。

根因是提交阶段的免扣费语义没有贯穿异步任务落库、退款和差额结算。

## 已有复现证据

使用本地 SQLite 和模拟上游，先提交任务成功，再查询得到失败状态。以下数字均为内部额度单位，不是货币金额：

| 阶段 | 用户钱包 | API Token 剩余额度 | 任务记录 |
| --- | ---: | ---: | --- |
| 提交前 | 10,000,000 | 10,000,000 | 尚未创建 |
| 提交成功后 | 10,000,000 | 10,000,000 | `BillingSource=user_owned_provider`，`Quota=500` |
| 查询确认任务失败后 | 10,000,500 | 10,000,500 | 错误增加 500 额度 |

原生视频提交入口 `/api/v3/contents/generations/tasks` 和通用提交入口 `/v1/videos` 均已复现，失败状态通过通用任务查询入口获取。覆盖 `seedance-yh` 视频 Profile，以及 `doubao-seedance-2` 视频 Profile 配合 `tgxmaas`、`volcengine-assets` 素材后端的可配置渠道；这些都是模拟测试，不代表直连官方视频服务实测。

已提交基线 `2fd000be583dcb06ed61ec6fc1814a14ff02f817` 与当时未提交的工作区均可复现，主代理也独立复现了 YH 原生提交场景。因此该问题不是这批未提交 YH 修复新增的回归；最早引入的提交尚未追溯。

## 影响与验证边界

- **已复现：** 失败的自有供应商视频任务错误增加钱包及 Token 额度。不同失败任务可分别触发，公共计费路径的影响不限于 YH。
- **代码确认的其他入口：** [service/task_polling.go](../../../service/task_polling.go) 的后台失败轮询、符合退款条件的超时清理同样调用 `RefundTaskQuota`；超时清理对旧系统遗留任务有不退款判断。
- **代码分析发现的同源风险：** 非按次计费任务成功后，若发生差额结算，也会进入未排除自有供应商的资金与 Token 调整函数，可能错误补扣或退还差额。此场景尚未单独完成端到端复现。
- **记录偏差：** `LogTaskConsumption` 使用模型计价额度记录消费及用量，可能与实际零扣费不一致。
- 本次复现的直接触发是持久化任务转为失败；仅查询请求发生 HTTP 错误不等于已经触发退款。现有终态判断和条件更新有重复处理保护，尚无证据证明同一任务反复查询可无限退款。
- 普通钱包、订阅付费，以及聊天、正常异步图片路径，未因本问题被证明存在同样错误。异步图片通常保存实际预扣额度，自有供应商对应零，图片成功结算也有专门分支。
- 未审计生产余额和任务历史，不能据此认定线上已发生错误退款、损失或利用行为。

后续重新安排修复时，需要同时核对任务保存额度、消费日志、失败退款、成功差额结算及历史任务，并验证普通钱包和订阅路径；当前保持暂不处理状态。
