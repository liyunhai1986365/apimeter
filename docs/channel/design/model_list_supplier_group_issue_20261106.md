# 指定供应商后模型列表为空：待排查记录

记录日期：2026-11-06。状态：**按用户要求仅记录，暂不修改代码**。

## 用户反馈

- 令牌选择 `default` 时能正常获取模型。
- 指定一个供应商／分组后返回空列表，并非指定多个供应商。
- 用户将接口描述为 `/model`；本次代码检查和本地验证针对平台模型列表接口 `/v1/models`，尚未取得线上完整请求路径。
- 尚未取得目标分组名称、线上渠道分组绑定和模型能力记录，不能确定线上根因。

## 已确认的代码行为

- `controller/model.go` 的 `getModelListGroups` 对普通指定分组使用令牌的 `TokenGroup`；自动分组读取 `GetRequestAutoGroups`。
- `model/ability.go` 的 `GetGroupEnabledModels` 从 `abilities` 中按分组名精确查询启用模型，不会临时拉取上游模型。
- `ListModels` 随后执行令牌模型白名单和价格配置过滤；自用模式或用户允许未定价模型时有相应例外。
- 仅创建分组或在令牌中选中分组，不会自动把渠道加入该分组。正常保存渠道分组时会更新其能力记录。

## 本地验证与边界

使用 SQLite、真实 `TokenAuth` 中间件和本地 HTTP 请求验证，未调用真实供应商：

- 单个供应商正确关联启用渠道、且模型已定价时，旧式单分组令牌和只含一个分组的有序策略令牌都能返回模型。
- 同一渠道、同一已定价模型仅归属 `default` 时，查询 `default` 有模型，查询另一个分组为空；通过正常渠道更新流程加入该分组后，两者均返回模型。
- 令牌只允许未定价模型、且未开启允许未定价模型的设置时，返回空列表。

这些结果只说明可产生相同现象的条件，**不证明用户线上存在分组未绑定、能力记录异常或价格未配置**。单分组线上问题仍未复现、未修复。

## 排查中另行发现的问题

以下为本地已复现的独立问题，不能用来解释用户的单分组反馈：

1. 模型列表没有读取完整 `GroupPolicy`；指定多个供应商时，只查询第一个分组，遗漏后续分组的模型。
2. 智能路由模型列表没有应用策略中的 `excluded_groups`，会列出被排除供应商独有的模型；排除全部候选组时，列表也未遵循空候选集。

曾在工作区尝试让模型列表复用路由策略解析，并新增 32 个场景验证；相关测试通过。**该实现和新增测试已全部撤回，没有 commit、tag 或 push。** 后续若重新处理，应独立评估权限、分组映射和各协议模型列表的兼容性。

## 后续定位所需信息

- 线上完整请求路径、所选分组的实际名称，以及令牌的分组策略和模型限制（无需提供 API Key）。
- 相关渠道是否启用、是否绑定目标分组；渠道配置与 `abilities` 记录是否一致。
- 对同一模型逐步核对：分组能力查询、令牌白名单、价格过滤，确认在哪一步变为空列表。
