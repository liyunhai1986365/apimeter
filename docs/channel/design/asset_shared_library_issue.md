# 多渠道共享同一素材库：待处理问题

记录日期：2026-10-08。状态：**已记录，暂不实现**；当前优先处理素材归属登记的 MySQL 死锁。

## 问题与当前行为

渠道 A、B 可能使用同一上游账号、项目和素材库，但当前素材归属同时绑定 `ChannelID` 和账号 `Scope`。素材经 A 登记后，指定 B 查询、删除或引用生成视频，可能返回 `asset_not_found`；不指定渠道时通常路由回 A，也不代表已支持 B 共享。

涉及 `controller/asset_access.go` 的渠道解析和归属校验、`controller/asset_list.go` 的列表过滤、`controller/asset_video_access.go` 的视频路由，以及 `model/asset_binding.go` 的登记冲突检查。多个素材分别绑定 A、B 时，即使实际在同一素材库，也可能无法组合用于同一个视频请求。

当前按素材句柄设置的跨渠道互斥锁用于保证并发归属登记的原子性，并不是所有素材共用一把锁。共享能力的限制主要来自渠道/账号身份与权限校验；不能通过简单删除互斥锁或 `ChannelID` 判断解决。

## 后续方案候选（无需改变数据库结构）

1. 在现有渠道配置 `setting.protocol.asset_library` JSON 中增加可选 `shared_library_id`。只有管理员明确配置相同且非空的标识，才声明渠道共用素材库；未配置时保留现有行为。**该字段目前尚未实现。**
2. 保留历史绑定和原始 `ChannelID` 作为来源，运行时解析共享库成员关系；不增加表、列或批量迁移历史记录。
3. 共享仍须满足同一用户、目标 Key/分组/渠道权限，以及实际账号、项目、后端兼容性。不能仅凭相同域名、素材 ID 或加密后的凭据判断同库。
4. 复用同一归属，列表合并去重；删除须使共享库内相关绑定同时失效，防止旧别名或并发查询恢复已删除素材。
5. 引用素材生成视频时可选择同库内获授权的渠道；已创建的视频任务仍按任务原渠道查询。
6. 保留并发互斥、归属冲突检查和撤销检查。加入共享关系前检查历史归属冲突，不能把其他用户的资源自动授予当前用户。

“不改数据库结构”仍允许保存现有配置和正常状态记录。此方案只解决多个渠道访问**同一真实素材库**，不同供应商之间的复制/同步另见 [Seedance 统一素材管理设计](seedance_unified_asset_design.md)。Key 跨分组权限问题也需独立验证，不因配置共享关系而自动放行。

## 实施时的验收范围

- A 创建，B 查询、列表展示和生成视频；B 删除后 A 的相关别名也失效。
- 其他用户、无目标渠道权限的 Key、其他素材库均被拒绝。
- 同库多个渠道登记的素材可组合引用，列表不重复。
- 并发首次登记只有一个合法归属；登记与删除并发不会恢复已撤销资源。
- 未配置共享关系时旧行为保持一致，兼容 SQLite、MySQL 5.7 和 PostgreSQL。

本次死锁修复不实现上述共享方案，不调整现有素材可见范围。
