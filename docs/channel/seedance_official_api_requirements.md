# Seedance 官方视频任务接口适配需求

- 整理日期：2026-09-14
- 状态：网关实现、Mock/race 与真实 cgt→MOV/末帧/usage 闭环通过；2026-09-15 17:53 的最小 duration=-1 请求已真实完成并返回 5 秒视频（此前拒绝记录保留为历史）；2.5 文生视频 bitrate_mode=vbr 仍未通过
- 实施与验收记录：[验证报告](seedance_official_api_verification.md)
- 协议依据：火山方舟官方文档，以及本仓库当前实现

## 1. 目标与原则

客户端通过本中转服务使用火山官方视频任务协议，完成“创建视频任务 → 取得官方原始任务 ID → 查询任务 → 获取官方结果及用量”的闭环。

本次范围调整：暂不处理素材库和分组，先整理并完善视频任务创建、查询接口能力。

原始需求列表中的“支持”“不支持”“不返回”“支持配置”等尾部标注不作为约束。以功能本身为目标：返回官方原始任务 ID、完整用量及官方链接，保留官方请求字段和响应语义。

本期优先复用现有任务存储和渠道配置，不以修改数据库表结构为前提。原始任务 ID 查询仍需执行用户归属校验；是否需要索引优化，按现有存储方式决定。

## 2. 本期范围

### 2.1 视频任务

修改以下接口的官方 Seedance 创建、查询链路：

```text
POST /api/v3/contents/generations/tasks
GET  /api/v3/contents/generations/tasks/{id}
```

“适配官方接口”指上述两项操作的请求、响应、任务状态、错误和 ID 使用方式与官方协议兼容，同时保留中转服务自身的鉴权、用户归属和计费能力。

本期不扩展视频任务列表、取消、删除等其他操作。不以修改通用 `/v1/videos`、`/v1/video/generations` 协议为目标；共享代码的调整需避免破坏这些既有接口。

### 2.2 不在本期范围

- 官方素材创建、查询、分组及 AK/SK 素材库鉴权接入，暂缓处理。
- 通用视频接口的功能扩展。
- 视频任务列表、取消、删除等其他操作。
- 新增任务并发控制、RPM/QPS 配额与压测容量承诺。

### 2.3 当前能力与改动清单

以下结论针对原生 Seedance 链路，不代表其他通用协议或任意第三方渠道行为。

| 能力 | 当前代码 | 本期处理 |
| --- | --- | --- |
| 七个请求字段及嵌套结构 | 原生请求通过 map 保留字段 | 验证透传及显式零值保留，避免回归 |
| `duration=-1` | 已允许并保留 | 验证实际发送值，不让预扣费估算覆盖它 |
| 创建返回原始任务 ID | 当前返回本地 `task_...` | 改为响应 `id` 返回官方原始 ID |
| 用原始 ID 查询 | 当前主要以本地任务 ID 查找 | 增加带用户归属限定的原始 ID 查找，兼容旧 ID |
| 查询响应 | 当前由适配器提取并重建字段 | 完善官方字段、状态和错误保留，核对缓存降级行为 |
| `usage` | 覆盖当前官方已公开字段，采用字段提取 | 完整保留对象，兼容未来新增用量明细 |
| 视频和末帧链接 | 已返回上游链接 | 保持官方原值并验证 |
| `bitrate_mode` 官方模型支持 | 中转能透传，官方文档未列出 | 不阻断透传，官方实际支持性单列待确认 |

## 3. 视频请求要求

客户端按官方结构在 JSON 顶层传递参数，不要求改放到 `metadata`。

| 字段 | 目标行为与限制 |
| --- | --- |
| `seed` | 原样透传，显式 `0` 不丢失 |
| `return_last_frame` | 原样透传，显式 `false` 不丢失 |
| `execution_expires_after` | 原样透传，由火山执行任务过期规则；文档范围为 3600–259200 秒，默认 172800 秒 |
| `tools` | 保留整个工具配置，包括 `web_search`；是否可用受模型支持范围限制 |
| `safety_identifier` | 原样透传，不套用聊天接口的默认移除逻辑；官方要求固定且唯一的英文字符串，最长 64 个字符 |
| `bitrate_mode` | 保留并透传；本次读取的官方创建文档未列出该字段，官方实际支持情况待确认 |
| `output_format` | 透传 `mp4` / `mov`，实际支持范围以具体模型的官方说明为准 |
| `duration` | 保留 `-1`，不转换为固定时长后发送；由模型选择实际时长 |

其他官方字段及嵌套结构也应保留，不仅限于上述列表。未传入的可选字段不擅自补值，显式零值和布尔假值不因序列化而丢失。

保留渠道模型映射能力；除必要的路由和模型映射外，不意外改写请求语义。预扣费估算与实际发送参数分离，不能将估算时长写回上游请求。

官方文档中，`duration=-1` 有模型范围限制；不能将中转能够透传等同于所有 Seedance 型号都接受。`bitrate_mode` 同样只承诺中转透传，不在未验证前宣称官方已支持。

## 4. 任务 ID 与查询

### 4.1 创建响应

- 创建成功时，响应主字段 `id` 返回上游火山生成的原始任务 ID（通常为 `cgt-...`）。
- 不再将该原生接口的响应 `id` 替换成本地 `task_...`。
- 本地任务 ID 可继续用于内部存储、计费和管理，不要求删除或替换已有记录。

### 4.2 查询行为

- 客户端可以直接用创建响应中的原始 ID 调用查询接口。
- 按原始 ID 查找时必须校验当前用户归属，并使用任务原渠道及对应凭证访问上游。
- 兼容已有本地 `task_...` 查询入口，不使历史任务失效。
- 原始 ID 和本地 ID 的解析顺序、可能的重复记录与查找性能，应在实现时明确。
- 不允许通过传入任意上游 ID 绕过本地任务归属检查。

## 5. 视频响应要求

### 5.1 官方语义保留

- 原生创建、查询响应尽量保留官方结构和字段，避免手工白名单重建导致遗漏。
- 保留官方任务状态，包括排队、运行、成功、失败、取消、过期等状态，不在原生响应中替换为通用视频协议状态名。
- 保留上游错误码和错误信息；不把上游失败伪装为成功。
- 对缓存、历史记录和上游查询失败后的降级响应，明确来源与行为，不编造尚未获得的成功结果或用量。

### 5.2 完整用量

- 上游返回 `usage` 时，完整保留该对象、嵌套字段和显式零值。
- 当前官方文档列出的字段为 `completion_tokens`、`total_tokens`、`tool_usage.web_search`，现有代码已覆盖这些字段。
- 完整保留对象是为避免未来新增明细丢失，不代表目前已确认存在官方用量字段遗漏。
- 上游未返回用量时不臆造数据；已有计费逻辑独立读取必要字段。
- 重复查询不得造成重复结算或重复退款。
- 本期要求返回完整用量，不因原列表“支持配置”的标注额外引入返回开关。

### 5.3 官方链接

- 返回官方 `content.video_url`。
- 上游返回末帧时，保留 `content.last_frame_url`。
- 不隐藏、替换为代理链接或承诺延长官方 URL 有效期。

## 6. 存储、归属与渠道约束

优先复用现有上游任务 ID、本地任务 ID、用户归属、渠道和原始响应存储。先检查原始 ID 的查询方式和性能，再决定是否需要索引或其他结构调整，不预先承诺绝对不改表。

- 创建任务后，继续保存本地任务与原始任务 ID 的对应关系。
- 按原始 ID 查询时限定当前用户；查询成功后使用任务保存的渠道及对应凭证访问上游。
- 不根据当前渠道优先级重新选择一个无关渠道查询历史任务。
- 原始 ID 存在歧义时不能任意选择记录，需要明确冲突处理规则。
- 对未归属当前用户的 ID 返回一致的不可访问结果，不直接拿任意 ID 到上游查询。

## 7. 验收标准

### 7.1 核心闭环

```text
调用原生创建接口，验证 duration=-1 及其他请求参数
→ 返回火山原始 cgt-... ID
→ 通过中转使用该 ID 查询任务
→ 返回官方状态、完整 usage、视频及末帧链接
```

上述参数应按具体模型允许的组合分别验收，不要求所有参数在同一个请求中同时使用。

### 7.2 必须覆盖的验证

- 请求中的 `0`、`false`、`-1` 及嵌套工具配置保留。
- 创建返回原始 ID，按原始 ID 查询成功，历史本地 ID 查询继续可用。
- 其他用户不能通过原始任务 ID 或本地任务 ID 查询不属于自己的任务。
- 上游新增的 `usage` 字段、嵌套字段和零值不被丢弃。
- 视频与末帧链接保持上游原值。
- 任务进行中、成功、失败、取消、过期，以及上游 HTTP 错误和限流均正确处理。
- 多渠道场景中，任务查询始终使用任务所属渠道及对应凭证。
- 重复查询与并发查询不造成重复结算。
- 共享实现调整不破坏既有通用视频接口。

使用模拟上游测试协议与异常场景，再用已授权的火山账号完成真实闭环验证。模拟测试通过不能替代官方模型实际支持性验证。

### 7.3 测试准备

1. 在测试环境部署待验收版本，记录代码提交、数据库类型、渠道类型和渠道模板（如有）。
2. 配置直接连接火山官方的渠道、模型映射及可用凭证，确认测试模型支持所选参数组合。
3. 准备用户 A、用户 B 的中转 Token，以及用户 A 的历史 `task_...` 任务，分别用于正常查询、越权验证和历史兼容验证。
4. 准备模拟上游：可捕获请求体，返回固定原始任务 ID，按测试步骤提供进行中、成功、失败等响应，并统计调用次数。
5. 记录测试前任务、用量日志和账户额度快照。后续使用只读查询核对任务映射、渠道及结算变化；测试记录不保存真实密钥。
6. 真实火山请求会产生任务及费用；使用已授权的测试账号和测试额度。本文示例仅作为后续验收操作，不表示已执行。

### 7.4 模拟上游自动化验证

仓库提供独立的字节/火山视频协议 Mock：[`scripts/seedance_mock/server.py`](../../scripts/seedance_mock/server.py)。启动、场景、渠道接入和测试步骤见 [Mock 使用说明](../../scripts/seedance_mock/README.md)。

必须将测试中转渠道指向 Mock，并通过中转的公开接口发起请求，以验证请求转换、任务存储和响应处理。仅直接调用 Mock 或其自测通过，不算中转接口验收通过。Mock 自测已与业务验收分开；未执行的业务验收项仍保持待验证。

应覆盖完整路由、鉴权、任务落库、适配器与查询响应，而不只验证单个序列化函数。优先扩展已有 Seedance 契约测试及任务集成测试。

| 编号 | 输入或场景 | 预期结果 |

| T02 | 分别传入七个关注字段、嵌套 `tools` 和额外扩展字段 | 请求结构及值保留；`bitrate_mode` 仅验证透传，不据此认定官方支持 |
| T03 | 上游创建返回固定 `cgt-test-001` | 客户端响应 `id` 为该原值；本地任务记录保存对应关系和所属用户、渠道 |
| T04 | 用户 A 用 `cgt-test-001` 查询；模拟状态由进行中变为成功 | 上游查询使用正确原始 ID；响应 ID、官方状态和结果一致 |
| T05 | 成功响应包含额外字段、嵌套用量明细、零值以及视频和末帧链接 | 官方业务响应字段保留，完整 `usage` 不被裁剪，链接保持原值 |

| T07 | 用户 A 用历史本地 `task_...` 查询 | 能解析到原任务并正常查询；返回的原生响应按原始任务 ID 语义处理 |
| T08 | 用户 B 用 A 的原始 ID、本地 ID 查询；另测不存在的 ID | 按既定不可访问策略拒绝；不返回任务内容，也不调用上游代查该任务 |
| T09 | 创建后改变其他渠道优先级，再查询原任务 | 仍使用任务保存的渠道和对应凭证，不漂移到其他账号 |
| T10 | 上游返回失败、取消、过期，或 HTTP 4xx/5xx、429 | 保留可用的官方错误和状态；不伪装成功；正确处理应退款的终态 |
| T11 | 上游查询超时或不可用，分别测试有终态缓存、无终态缓存 | 按明确的降级策略响应；不编造新状态、链接或用量，不泄漏原始内部封装 |
| T12 | 成功/失败终态重复查询，并让前台查询与后台轮询并发完成 | 最终状态一致，结算或退款最多生效一次 |
| T13 | 上游创建成功、本地保存失败；或原始 ID 查找存在歧义 | 按实现设计返回可追踪错误或执行补偿，不静默串任务，不盲目重复创建收费任务 |
| T14 | 既有 `/v1/videos`、`/v1/video/generations` 回归 | 既有公开 ID、请求和响应契约不因原生接口修改而意外变化 |

HTTP 错误与任务业务失败应分开测试：查询 HTTP 200 且任务状态为失败，不等同于查询请求本身失败。缓存降级和本地保存失败策略须在实现设计中确定后，写成明确断言。

### 7.5 真实火山端到端闭环

#### 步骤一：创建任务

设置测试变量，`SEEDANCE_MODEL` 填中转公开模型名或已配置的映射名，并确认其对应模型支持 `duration=-1` 和末帧返回：

```bash
export SEEDANCE_GATEWAY='https://你的中转域名'
export SEEDANCE_MODEL='已配置且支持本次参数的模型名'
# SEEDANCE_TOKEN 通过测试环境的安全方式注入，不写进文档或版本库。

curl -sS -D /tmp/seedance-create.headers \
  -o /tmp/seedance-create.json \
  -w 'HTTP %{http_code}\n' \
  "${SEEDANCE_GATEWAY}/api/v3/contents/generations/tasks" \
  -H "Authorization: Bearer ${SEEDANCE_TOKEN}" \
  -H 'Content-Type: application/json' \
  --data "{\"model\":\"${SEEDANCE_MODEL}\",\"content\":[{\"type\":\"text\",\"text\":\"一只小猫在窗边伸懒腰，镜头缓慢推进\"}],\"duration\":-1,\"seed\":0,\"return_last_frame\":true}"
```

验收：HTTP 请求成功；响应 `id` 等于本次火山原始任务 ID，而不是本地 `task_...`。记录 `X-Oneapi-Request-Id` 及可获取的上游请求 ID，用于关联日志。不能仅凭 `cgt-` 前缀认定正确，还要对照上游响应或内部任务映射。

#### 步骤二：用创建响应中的 ID 查询

从成功响应读取 `id`（以下使用 `jq`），再查询：

```bash
SEEDANCE_TASK_ID=$(jq -er '.id | select(type == "string" and length > 0)' /tmp/seedance-create.json)

curl -sS -D /tmp/seedance-fetch.headers \
  -o /tmp/seedance-fetch.json \
  -w 'HTTP %{http_code}\n' \
  "${SEEDANCE_GATEWAY}/api/v3/contents/generations/tasks/${SEEDANCE_TASK_ID}" \
  -H "Authorization: Bearer ${SEEDANCE_TOKEN}"
```

按账号配额，以合理间隔重复查询直至终态；可从 5–10 秒间隔开始，遇到 429 按可用的重试提示退避。设置测试等待上限，达到上限时记录“未完成”，不能直接认定成功或触发重复创建。

验收：响应 ID 与创建结果一致，任务能从非终态进入终态。任务实际生成时间不同于提交时的 `-1`，应以官方查询结果为准。中转不把本地状态名当成官方状态返回。

#### 步骤三：核对结果和用量

- 成功时取得 `content.video_url`；申请末帧且上游返回时，取得 `content.last_frame_url`。
- 在 URL 有效期内下载并验证文件可播放/可打开，不仅检查字段非空。
- 对照本次任务保存的原始上游查询响应，比较 `id`、`status`、`content`、`usage` 及其他官方字段；同一时刻的终态响应更适合比较。
- 核对 `usage` 中 token 和工具用量保留，不要求未启用的工具字段凭空出现。
- 再查询数次，核对额度及用量记录，确认没有重复结算。

不要为比较结果重复提交相同生成请求：不同任务的输出及用量可能不同，也会额外产生费用。

#### 步骤四：独立验证其他参数

基于已通过的基础请求，每次只改变一个参数或一组官方要求关联的参数，记录模型版本与结果：

| 参数 | 验证方式 |
| --- | --- |
| `return_last_frame=false` | 验证发送值保留，按官方行为判断末帧响应 |
| `execution_expires_after` | 传合法阈值验证接受；实际过期终态主要用模拟上游覆盖，避免为测试长期等待 |
| `tools` | 在支持模型中传 `[{"type":"web_search"}]`；模型可能不执行搜索，`web_search=0` 也是有效结果 |
| `safety_identifier` | 传符合官方长度限制的测试用户哈希标识，验证透传及官方返回行为 |
| `output_format` | 在支持模型中分别验证 `mp4`、`mov`，下载核对实际格式；不只按 URL 后缀判断 |
| `bitrate_mode` | 待确认官方参数值和模型范围后单独验证；未确认时标记待验证，不并入基础成功用例 |

#### 步骤五：权限与历史兼容

用用户 B 的 Token 查询用户 A 的任务，验证被拒绝且不泄漏结果。再用用户 A 查询既有 `task_...` 历史任务，验证查询仍可用。
