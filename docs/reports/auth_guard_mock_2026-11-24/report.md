# 本地认证与防猜测验收（2026-11-24）

在当前工作树（HEAD `6911ddedc` 加本地改动）编译网关，使用独立的 MySQL 5.7.44、Redis 7、普通用户和管理员测试身份，服务只监听回环地址。最后一轮共 **84/84 项 HTTP 验收断言通过，覆盖 54 个不同路径；39/39 个 Go 专项测试通过**。没有观察到被测入口接受错误凭证。这个结论不证明生产没有遭受攻击，也不表示每条路由都跑过真实登录或第三方交互。

## 需要处理的风险

| 优先顺序 | 证据与影响范围 | 建议 |
|---|---|---|
| 1. 密码登录缺少按账号的失败预算 | [登录验证](../../../controller/user.go#L42)调用[密码核对](../../../model/user.go#L1025)，错误路径不累计该账号的密码失败次数。现有关键操作窗口按来源地址，所有关键操作共享该窗口；[会话签发限制](../../../service/auth_session.go#L72)在凭证通过后才生效。对只用密码的账户尤其重要。正常登录、错误密码、429 和恢复均已实测；账号维度的缺口来自代码核对。 | 在保留来源限流的同时，为规范化登录标识增加共享的失败计数和渐进延迟；控制延迟上限，避免恶意错误输入使账号长期不能登录。管理员优先启用 2FA。 |
| 2. 邮箱短码没有独立尝试上限，消费语义也不完整 | [验证码存储](../../../common/verification.go#L47)只检查是否相等、是否过期。注册与绑定使用同一邮箱验证用途，成功流程未见删除此用途的验证码。重置密码另用长随机令牌，成功后会删除，但[检查和删除](../../../controller/misc.go#L565)分开。发信窗口按来源，不等于对特定邮箱或 challenge 限次。代码核对；未发送真实邮件或尝试猜中验证码。 | 为每个邮箱及用途限制发送与失败次数，校验成功后一次性消费；多实例共享状态，保留重置邮件对外的一致响应。 |
| 3. 中转模型限流不保护无效 API Key 的校验成本 | [中转路由](../../../router/relay-router.go#L80)先鉴权，后做模型请求限流。未带凭证和固定错误凭证均被拒绝；某些非空无效凭证仍会触发[令牌查询](../../../model/token.go#L323)。这涉及日志和数据库容量，不代表长随机 API Key 已被猜中。 | 在入口代理按来源控制未认证流量，在应用聚合认证失败指标；避免用模型限流代替这一层，也不要影响已认证模型的配额规则。 |
| 4. 公开图片依赖链接而非用户身份 | [Midjourney 图片读取](../../../relay/mjproxy_handler.go#L29)按任务标识检索；平台渠道校验不等于校验图片所有者。链接转发或泄露可能让其他人看到内容。未测真实资源，未证明标识可猜。 | 若产品承诺图片私有，校验归属或改用短时签名链接；若有意允许分享，明确链接权限和过期规则。 |
| 5. 邮箱注册状态和兑换日志 | [发注册验证邮件](../../../controller/misc.go#L493)对已经占用的邮箱返回可区分消息；[兑换失败日志](../../../controller/user.go#L1728)包含客户端提交的完整兑换码。二者都是代码证据，不是已经猜中凭证的证据。 | 注册邮件统一对外响应；日志只记内部请求号、错误类型或不可逆摘要。 |

## 运行时验证

| 已验证场景 | 结果及边界 |
|---|---|
| 登录与初始化 | 正常凭证登录成功，错误密码不签发认证信息；已初始化的服务拒绝再次初始化。 |
| 关键操作窗口 | 23 个已知关键操作在临时 Redis 窗口已满时全部返回 429 并包含 Retry-After。覆盖登录、注册、找回、登录二次验证、Passkey 登录、OAuth、账户密钥、令牌提取、订阅密钥和兑换入口。另对同一合法登录实际跨过一次阈值，验证最后一个名额可用、下一次拒绝、过期后恢复。 |
| 验证码与邮件 | 三项专用限流断言通过：图形验证码生成和校验共享一个窗口，发注册验证码使用另一个窗口。图形 challenge 的绑定、失败消耗和一次性使用有 Go 回归覆盖。没有实测发送邮箱验证码后的完整注册、绑定及重置闭环。 |
| 二次验证与备用码 | 测试用户实际开通 TOTP，正确密码只签发二次验证流程。将其失败计数预置在阈值前一格，一个不属于测试用户的合法格式备用码触发 MySQL 账号锁；锁定时其有效备用码也被拒。把测试锁置为已过期后，有效备用码成功，已完成的流程不能重复使用。 |
| API Key、敏感管理入口与 SSO | 32 项无凭证请求受到拒绝，包括控制台、Passkey、账户绑定、密钥读取、兑换、管理页、OpenMosaic 和代表性中转路径；另 4 个入口以固定无效 Bearer 被拒。普通用户操作另有 2 项拒绝断言。未配置支付的兑换检查没有深入验证真实兑换码；OpenMosaic 未配置有效第三方客户端。 |
| 支付回调 | Stripe、Creem、Waffo、Waffo Pancake 在未配置支付时，四个回调均返回 403。未把“功能关闭”计作已启用支付时的签名或重放测试。 |

[HTTP 断言清单](http-checks.tsv)只保留场景、路径、状态与结果；部分应用采用 HTTP 200 加业务拒绝，判断时检查了响应体，未把 HTTP 200 一律算作成功。[Go 专项清单](go-tests.tsv)包含 Redis 窗口、代理信任、失败计数并发更新、备用码一次性、OAuth 流程、Passkey 前置证明等。

## 范围和环境

- [路由目录](routes.tsv)有 **657 个已注册 method/pattern**。通过本地 Gin 注册表提取 API、Dashboard、Relay、Video 及动态 profile 路由；目录遍历在运行处理器前停止，不含前端静态资源，不能当作 657 次鉴权业务测试。
- 密码登录、刷新、注册、OAuth 等关键窗口本轮使用缩小的额度 6，图形验证码额度 2；默认关键窗口为 20 次/1,200 秒。夹具仅对私有测试 Redis 和 MySQL 预置计数或过期时间，不靠大量失败请求触发边界。直连模式设为 `TRUSTED_PROXIES=none`。生产前面若有反代，应显式信任实际代理地址并确保源站不能被公网直连；本轮未读取生产代理配置。
- 摘要只统计最后一轮。早先的夹具密码长度、格式无效的备用码、机器临时盘过满分别触发了其他保护；修正测试输入和网关临时目录后重新创建环境，未修改业务代码。
- 外部 OAuth/Passkey 硬件、真实 SMTP、已启用支付的签名往返、WAF/CDN、生产日志和攻击来源未在本轮验证。测试完成后已停止网关，并移除本轮的临时 MySQL、Redis 和数据。
