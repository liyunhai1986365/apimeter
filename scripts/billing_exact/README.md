# 本地 HTTP 精确扣费验收

这套测试用真实网关、MySQL 5.7.44、Redis 和本地上游 mock，按独立的 Decimal 公式逐笔核对用户余额、令牌余额、消费日志以及 Redis 用户额度。共 83 个场景：聊天 36、图片 29、视频 12、并发 5、重启后查询 1。

从仓库根目录运行。需要 Go、Python 3（安装 `requests`）、可以运行容器的本地 Docker，以及 `mysql:5.7.44` 和 `redis:7-alpine` 镜像。Go 编译会嵌入两个前端主题；全新检出时先按项目构建流程生成 `web/default/dist` 和 `web/classic/dist`。

```bash
go build -o /tmp/apimeter-billing-test .
python3 scripts/billing_exact/run.py --binary /tmp/apimeter-billing-test
```

脚本不读取现有数据库配置。每次运行都在随机回环端口启动独立的数据库容器、网关和上游，仅移除本轮容器。向脚本发送 `SIGTERM` 后，它会在当前操作结束后停止，关闭网关和上游并清理本轮容器，退出码为 143。网关通过 `--listen-host 127.0.0.1` 只接受本机连接；不使用该参数的部署沿用原监听行为。渠道使用正常的 60 秒缓存同步周期，启动后会等待路由可用，再开始对账。

聊天和图片别名逐次核对 mock 实际收到的上游模型名。并发的 200 个非流式聊天响应逐条核对对应渠道的完整文本、助手角色和正常结束标记；20 个并发图片响应逐条核对返回的图片。并发创建的 10 个视频、完成后重复查询 20 次的图片或视频，以及重启后的已完成任务，每次查询都要求返回 HTTP 200、原任务 ID 和 `succeeded` 状态。图片还核对张数和内容：内联图片与 mock PNG 比对，临时图片链接须能从本机网关取回相同字节。重复查询和重启后的对账还要求没有新增扣费或消费日志。

启动时打印本轮结果目录。查看 `exact-accounting.json` 获取各场景的公式、应扣和实扣；`checks.json` 包含其余断言。仅当 83 项均通过、其余检查无失败且容器清理成功时进程返回 0。结果目录仅当前用户可读，`private/` 下有本地测试日志。覆盖范围是指定配置和 mock 用量，不校验供应商真实账单。
